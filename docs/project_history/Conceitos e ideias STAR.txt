# 🏛️ Cada sala precisa ter uma "regra de realidade"

Acho que esse deve virar um princípio oficial do STAR WORLD.

Cada ambiente possui:

- **função**
- **objetos disponíveis**
- **ações permitidas**
- **conhecimento especializado**
- **limitações**
- **resultados**
- **consequências**
- **memória própria**

Por exemplo:

### 🛠️ Central de Criação

**Propósito:** transformar ideias em objetos, máquinas e projetos.

Pode:

- projetar;
- montar;
- desmontar;
- programar;
- simular engenharia;
- testar mecanismos;
- trabalhar com protótipos.

Não pode simplesmente resolver uma reação química complexa ali.

Para isso:

**Central de Criação → Laboratório.**

---

### 🧪 Laboratório

**Propósito:** ciência e experimentação.

Pode:

- cálculos;
- química;
- biologia;
- materiais;
- análise;
- experimentos;
- simulações.

E aqui aparece uma distinção importantíssima que você colocou:

> **a STAR não "finge" que está fazendo ciência. O sistema tenta representar a ciência de maneira realista.**

Então um projeto como o Web Shooter poderia realmente ser dividido:

**Laboratório**
→ formulação do fluido

**Central de Criação**
→ mecanismo do lançador

**Laboratório + Central**
→ integração

**Teste**
→ resultado

**Memória**
→ projeto salvo

Isso já começa a parecer um **simulador de engenharia pessoal**.

## 🚨 E tem uma decisão técnica que eu considero essencial

**Não devemos começar a programar todas essas salas agora.**

Não porque a ideia seja grande demais — mas justamente porque ela é **boa demais para ser improvisada**.

Primeiro precisamos definir o **sistema que todas as salas terão em comum**.

Algo conceitualmente parecido com:

```text id="xji8i4"
STAR WORLD
│
├── Room System
│
├── Interaction System
│
├── Item System
│
├── Project System
│
├── Event System
│
├── Narrative System
│
├── Reality Classification
│
├── Memory System
│
└── World State
```

Depois:

```text id="2q02g9"
Room System
      ↓
Laboratório
Biblioteca
Jardim
Observatório
Cozinha
Estúdio
Quarto
Correio
Central
Cura
```

Assim, quando criarmos a décima sala, ela usa a mesma fundação.

**Isso evita exatamente o tipo de retrabalho que queremos evitar na STAR.**

E tem mais: como a versão atual ainda está em uma interface funcional relativamente simples — menu, chat, Brain e memória — o próximo salto visual pode ser planejado como uma evolução arquitetural, em vez de simplesmente colocar dez telas novas no `app.py`. fileciteturn0file12L1-L31
