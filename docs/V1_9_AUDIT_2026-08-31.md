# ⭐ STAR V1.9 — Auditoria de estabilidade (31/08/2026)

## Objetivo

Revisão estrutural da V1.9 antes de abrir definitivamente o desenvolvimento da V2.0 MIND.

A auditoria considerou:
- startup;
- interface;
- voz;
- STT/TTS;
- arquivos de referência;
- Core;
- Router;
- matemática;
- ferramentas locais;
- modo ONLINE/OFFLINE;
- banco local;
- assets;
- testes automatizados;
- CI;
- documentação.

---

## Correções aplicadas

### Startup
- removida a exigência de um arquivo chamado exatamente `star_reference.mp3`;
- a interface pode abrir mesmo quando a voz oficial estiver degradada;
- o launcher usa o `VoiceManager` como fonte de verdade para estado da voz;
- Chatterbox/referência deixaram de ser condição para iniciar a aplicação.

### Voz
- a referência pode ter nome diferente dentro de `voice/reference/`;
- o modo oficial continua usando Chatterbox;
- o modo rápido da interface prioriza Windows SAPI e depois Piper;
- o STT é pré-carregado sem carregar Chatterbox durante o startup;
- o teste oficial continua separado da voz rápida;
- falas antigas continuam canceláveis;
- o avatar volta ao estado neutro após a fala.

### Interface
- preferências de skin/voz passam a ser locais em `user_settings.json`;
- mudanças de preferência não sujam mais o arquivo `config_skin.json` versionado;
- assets de emoção vazios caem para o avatar neutral em vez de quebrar a imagem;
- botões ONLINE/OFFLINE agora refletem o estado ativo;
- o estado ONLINE/OFFLINE é propagado ao Core.

### Core e ferramentas
- comandos de internet respeitam o estado ONLINE/OFFLINE;
- ações locais continuam disponíveis offline;
- removida uma segunda interpretação matemática concorrente no final do pipeline;
- matemática principal fica centralizada em `core/math_engine.py`.

### Áudio de entrada
- corrigido descritor de arquivo temporário aberto por `mkstemp`;
- adicionado fechamento explícito do stream de gravação.

### Testes/CI
- corrigido teste que importava a classe inexistente `ChatterboxTTS`;
- testes antigos passaram a ser testes pytest reais;
- suite completa de `tests/` passa a rodar no workflow de qualidade;
- CI também cobre a branch `v2.0-development`;
- launcher e contrato de referência de voz ganharam testes.

### Dados locais
- `star.db` foi identificado como dado local que idealmente não deve ser versionado;
- nesta auditoria o arquivo legado foi **preservado temporariamente no repositório** para evitar que um `git pull` apague o histórico local de instalações existentes;
- o `.gitignore` permanece preparado para a futura migração;
- a migração segura do banco para um caminho local não versionado deve acontecer em uma etapa própria, com cópia/backup antes da remoção definitiva.

## Problemas encontrados que não bloqueiam a V1.9

### Chatterbox em CPU
Teste físico anterior:
- warmup: ~137 s;
- síntese curta: ~115 s.

Conclusão: funcional, porém inadequado para conversa em tempo real no hardware atual.
Por isso a GUI usa modo rápido por padrão, mantendo Chatterbox como voz oficial de alta fidelidade.

### Assets placeholder
Existem arquivos vazios/placeholder, por exemplo:
- vários estados de avatar;
- temas;
- `core/commands.py`;
- `core/reasoning.py`;
- `gui/chat.py`;
- `gui/theme.py`;
- `modules/automation.py`;
- `modules/internet.py`;
- `modules/vision.py`.

Eles não são carregados como capacidades reais na V1.9. Devem ser preenchidos ou removidos/arquivados nas gerações correspondentes.

### Código histórico
`core/brain.py` e alguns testes/arquivos antigos coexistem com a arquitetura atual.
Não participam do entrypoint principal e devem ser tratados como histórico até migração/limpeza planejada.

### Ícone
`assets/icons/star.ico` está vazio, enquanto existe outro arquivo de ícone válido com nome duplicado.
Não bloqueia a GUI, mas deve ser corrigido durante a próxima revisão visual.

## Critérios de validação local

Após atualizar a branch/release:

1. executar `python diagnostico.py`;
2. executar `DIAGNOSTICO_VOZ.bat`;
3. executar `INICIAR_STAR.bat`;
4. validar:
   - menu;
   - chat;
   - entrada por teclado;
   - microfone;
   - transcrição;
   - resposta textual;
   - resposta falada no modo rápido;
   - teste da voz oficial;
   - matemática;
   - HUB/ilhas;
   - Closet/skins;
   - fechamento da aplicação.

## Estado arquitetural

A V1.9 deve ser considerada uma fundação offline-first.

```text
LOCAL
  → Core
  → conhecimento interno
  → matemática
  → memória
  → GUI
  → STT
  → fala rápida local

ONLINE
  → adiciona web/Spotify/serviços autorizados

OFFICIAL VOICE
  → Chatterbox + referência local
```

A V2.0 MIND deve herdar esta base sem reintroduzir dependências frágeis no startup.
